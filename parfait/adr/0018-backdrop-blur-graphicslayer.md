# ADR-0018: 배경 블러 관용 — GraphicsLayer 캡처 + BlurEffect 재그리기

> 상태·날짜·결정자·대체 관계는 위 frontmatter가 단일 출처. 본문은 결정 내용에 집중.

## 맥락

Figma `Top Bar`의 `Status=Default`·`Status=Empty`가 반투명 배경(`Transparency.White75`) 위에
**2px 배경 블러**를 요구한다. 바 뒤로 콘텐츠가 스크롤해 지나가는 화면(G-001 그룹 목록)에서 바가
콘텐츠를 가리지 않으면서 텍스트 가독성을 유지하려는 장치다.

**Compose는 배경 블러를 기본 제공하지 않는다.** `Modifier.blur`와 `BlurEffect`는 *자기 자신과 자식*을
흐린다. 뒤에 있는 것을 흐리려면 배경을 별도 레이어로 캡처해 블러를 걸고 소비 표면 영역에 다시 그려야
하고, 그 배선은 **컴포넌트 단독으로 닫히지 않는다** — 무엇이 "뒤"인지는 호출 화면만 안다.

같은 요구가 이미 한 번 나왔다. C-101 카메라 뷰파인더의 프레임 안/밖 분리 블러(위키 [[카메라-뷰파인더]])가
2026-07-26에 **GraphicsLayer 2회 그리기**로 확정돼 있다. 이 결정은 그 관용을 프로젝트 규약으로 승격한다.

## 결정

**배경 블러는 외부 라이브러리 없이 `GraphicsLayer` 캡처 + `BlurEffect` 재그리기로 구현한다.**

- 배경 콘텐츠를 호출 화면이 `rememberGraphicsLayer()`에 `record`한다.
- 블러를 소비하는 표면(Top Bar)은 그 레이어를 **파라미터로 받아**, 별도 레이어에 복사하고
  `renderEffect = BlurEffect(...)`를 걸어 **자기 영역으로 clip해 다시 그린다.**
  원본 레이어에 직접 `renderEffect`를 걸지 않는다 — 같은 레이어가 배경으로도 그려지므로 블러가 번진다.
- **레이어는 컴포넌트가 만들지 않고 호출 화면이 소유한다.** 무엇이 블러 소스인지는 화면의 판단이고,
  디자인시스템 컴포넌트가 알 수 있는 정보가 아니다.
- 레이어 파라미터는 **nullable, 기본값 `null`**이다. `null`이면 블러 없이 틴트만 그린다. 갤러리·프리뷰처럼
  뒤에 스크롤 콘텐츠가 없는 맥락에서 억지로 레이어를 만들게 하지 않는다.
- **틴트(`White75`)는 블러와 독립적으로 항상 그린다.** 블러가 없는 조건에서도 가독성이 유지돼야 한다.
- API 31 미만 분기는 **진입점 한 곳**에서 판단한다(C-101이 세운 방식과 동일).

## 대안

- **대안 A: `dev.chrisbanes.haze` 도입** — 트리를 건너 소스↔이펙트를 잇는 배선을 대신 해주고
  다운샘플링 최적화가 붙어 있다. 그러나 **API 하한을 낮춰주지는 않는다**(`RenderEffect`가 API 31+라
  자체 구현과 제약이 동일하다). 얻는 것이 배선 편의뿐인데, C-101이 이미 자체 구현으로 확정돼 있어
  **한 앱에 블러 메커니즘이 둘** 생긴다.
  **→ 기각:** 이득이 편의에 그치는 반면 관용이 갈라지는 비용이 크다.
- **대안 B: 블러를 포기하고 틴트만** — 의존성도 배선도 늘지 않고, 75% 불투명 배경 위에서 2px 블러의
  시각적 기여가 크지 않다. 그러나 Figma 정본과 어긋난 채로 남는다.
  **→ 기각:** 정본 불일치를 남기지 않기로 함(작업자 결정).
- **대안 C: 반투명 배경 + 스크림 강화로 흉내** — 구현이 가장 싸다. 그러나 "뒤가 비쳐 보이되 흐리다"는
  의도가 사라져 다른 디자인이 된다.
  **→ 기각:** 요구를 충족하지 않는다.

## 영향

**긍정**

- 외부 의존성이 늘지 않는다.
- C-101과 **같은 관용**을 쓰므로 블러를 다루는 방식이 앱 안에서 하나로 유지된다.
- 레이어를 호출자가 소유하므로 디자인시스템 컴포넌트가 화면 구조를 알 필요가 없다.

**트레이드오프**

- 배선을 호출 화면이 직접 짠다 — 레이어 생성·record·전달이 화면마다 반복된다. 소비처가 셋을 넘으면
  공용 모디파이어로 묶는 것을 검토한다(지금은 둘이라 이르다).
- 소비 표면 공개 시그니처에 레이어 파라미터가 붙는다(기본값 `null`이라 기존 호출부는 무변경).

**위험·방어**

- ⚠️ **API 31 미만에서는 실제 블러가 없다.** `RenderEffect`가 API 31부터이고 이 프로젝트 `minSdk`는
  **26**이다. 26~30 기기에서는 틴트만 남는다. 플랫폼 제약이라 어떤 대안으로도 해결되지 않는다.
  → 틴트를 블러와 독립적으로 항상 그려 가독성을 보장한다.
- 레이어 좌표 정합 — 소비 표면이 배경 레이어 안에서 자기 위치를 알아야 올바른 영역을 흐린다.
  위치를 잘못 잡으면 엉뚱한 데가 흐려지고, 이건 스크롤 중에만 드러나는 종류의 결함이다.
  → 실기기에서 **스크롤하며** 확인한다. 정지 스크린샷으로는 잡히지 않는다.
  **2026-08-01 확인됨** — Galaxy A35(API 36) 갤러리에서 틴트 경계와 흐림 경계가 정확히 일치하고,
  스크롤 후에도 정합이 유지됐다. `onGloballyPositioned`의 루트 기준 좌표로 translate 하는 방식이
  의도대로 동작한다.
- 검증은 이 저장소의 디자인시스템 관례대로 **프리뷰 + 실기기 육안**으로 한다. 블러는 스크린샷 대조
  외에 자동 검증 수단이 마땅치 않다.
