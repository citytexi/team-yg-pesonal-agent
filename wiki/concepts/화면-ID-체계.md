# 화면 ID 체계

[[협업-캔버스-앱]] 기능정의서의 화면 식별 규칙. 접두사로 도메인 구분.

| 접두사 | 도메인 | 예 |
|---|---|---|
| `A-` | Auth (인증/온보딩) | A-001 스플래시([[스플래시-애니메이션]]), A-002 로그인 |
| `G-` | Group (그룹) | G-001 그룹 목록, G-002 그룹 진입([[기능정의서-v6]] 삭제 → [[기능정의서-v7]] **복원**) |
| `C-` | Canvas (캔버스/편집) | C-001 메인, C-101 촬영, C-304 캔버스 수정(C-301 파르페 편집은 v7에서 삭제) |
| `S-` | Sidebar (사이드 메뉴) | S-001 앱 메뉴, S-101 그룹 메뉴 |
| `SY-` | System (스케줄/자동) | SY-001 마감, SY-003 신규 생성 |
| `P-` | Push (푸시 알림, v7 신설) | P-01 토핑 등록, P-02·P-03 리마인드 → [[푸시-알림-정책]] |
| `Tutorial-` | 온보딩 튜토리얼 (v7 신설) | Tutorial-1~5 → [[온보딩-튜토리얼]] |

### v7 신설 접두사 2종의 예외성
`P-`와 `Tutorial-`은 기존 규칙에서 두 가지가 어긋난다.
- **`P-`는 번호가 2자리다**(`P-01`) — 나머지는 전부 3자리(`A-001`).
- **`Tutorial-`은 접두사가 약어가 아니라 낱말이고 번호도 1자리다**(`Tutorial-1`).
- 둘 다 **전용 화면 디자인이 없거나 곧 사라질 화면군**이다 — 푸시는 OS 시스템 푸시라 화면이 없고, 튜토리얼은 삭제가 예고돼 있다.

## 서브 ID (v5~)
[[기능정의서-v5]]에서 확인/에러/로딩 화면에 하이픈 서브 ID 도입:
- `C-101-confirm`, `C-101-error`, `C-102-confirm`, `C-102-error`
- `C-103-loading`, `C-103-select`
- `SY-001-closed`, `SY-001-new`

### 대소문자 통일 (v7)
[[기능정의서-v7]]에서 위 8건의 접미사 첫 글자를 **대문자로 통일**했다 — `C-101-Confirm`·`C-103-Loading`·`SY-001-Closed` 등.

> ⚠️ [2026-09-21] **통일이 행 ID에만 적용됐다.** 다른 행의 `다음 단계`·`진입 경로` 셀에는 `C-101-confirm`·`C-103-loading` 같은 구 소문자 표기가 그대로 남아 있다 → [[open-questions]]

### 서브 ID의 성격 변화 (v7)
v5~v6의 서브 ID는 **표에 행이 없는 상태 이름**이었으나, v7은 상태 화면 6건을 **독립 행으로 승격**했다 — `C-001-Loading`·`C-001-Error`·`G-001-Error`·`C-102-Empty`·`G-001-Empty`·`C-103-Error`.

그러면서 **행으로 올릴 것과 상태로 남길 것을 가르는 기준**을 원본이 처음 명시했다. "별도 페이지인가"가 기준이고, 아래는 행이 아니라 상태로 남긴 것들이다.
- `C-001-2depth`(메뉴 펼침 상태) · `C-001-Empty`(토핑 미설정 상태) · `C-001-Saved-Toast`(성공 토스트)
- `A-004-Confirm`·`A-005-Confirm`(확인 모달) · `C-305-Modal`(삭제 확인 모달) · `C-304-Color/Img/Modal`(배경 설정 예시)
- `C-101-Toast`·`C-102-Toast`(진입 시 안내 토스트) · `C-102-Reselect`(Empty 내 부분 권한 분기)
- `G-001-1~5`(그룹 수별 예시) · `A-002-1/2/3`(온보딩 가로 스크롤 그래픽 순서)
- `C-201-SelectYear`·`C-201-SelectMonth`(드롭다운 열린 상태)

## 화면 ID 밖 — 공용 정책 문서

화면 비종속 공용 규칙을 다루는 정책 문서는 이 접두사 체계에 들어가지 않는다. 선례가 둘이고 명명이 서로 다르다.

- [[common-공통-로딩-정책-v0.1]] — 접두사 `common-`. 앱 전역 로딩 애니메이션([[공통-로딩]]).
- [[C-103-이미지-렌더링-정책-v0.1]] — 이름에 `C-103`이 붙어 있으나 **내용은 화면 비종속**이다([[이미지-렌더링-정책]]). 최초 정의 화면이 C-103이었을 뿐이므로, 파일명을 화면 귀속으로 읽으면 안 된다.

## 변화
- A-003의 의미가 버전에 따라 바뀜: v2~v4 "진입 경로 선택" → v5 "약관 동의". v5~v6에서 A-004·A-005가 여전히 A-003을 진입 경로로 참조해 흐름이 어긋났으나 v7에서 해소됐다(아래 참고).
- 편집 화면(C-1xx/C-3xx) 번호는 v3·v5에서 재배치됨.
- **G-002(그룹 진입) 삭제 후 복원**: v4·v5 캡처 누락이던 G-002가 [[기능정의서-v6]]에서 완전히 제거됐다가, [[기능정의서-v7]]에서 **복원**됐다. v7의 `v7 상태` 컬럼이 이 행만 `복원`으로 표기한다. "그룹 권한 유효 여부" 분기도 함께 돌아와 권한 검증 위치 미결이 종결됐다.
  - 한 화면이 **삭제됐다가 되살아난 첫 사례**다. 판본 간 화면 구성은 단조 증가·감소가 아니다.
- **C-301(파르페 편집 모드) 삭제([[기능정의서-v7]])**: v6 비고 "에딧 모드 삭제"가 v7에서 실제로 반영됐다 — 표 갱신 누락이었다. 편집 모드 진입은 **C-304가 배경 탭·토핑 탭으로 흡수**했고, 진입점은 C-001 Canvas-Menu 1뎁스의 "캔버스 편집 >"이다. C-302·C-303·C-305의 진입 경로도 C-301 → C-304로 재배선됐다.
- **A-003 흐름 정리([[기능정의서-v7]])**: A-004·A-005의 진입 경로가 `A-003`(약관 동의) → **`G-001`**(그룹 목록)로 바뀌었다. 그룹 참여·생성은 약관 동의 직후가 아니라 그룹 목록에서 시작한다.
