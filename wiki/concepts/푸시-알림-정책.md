# 푸시 알림 정책 (P-01~P-03)

[[협업-캔버스-앱]]이 앱 바깥으로 내보내는 OS 시스템 푸시. [[기능정의서-v7]]에서 접두사 `P-`와 분류 `Push`가 함께 신설되며 처음 정의됐다. **전용 화면 디자인이 없는 유일한 화면군**이다 — 원본이 "앱 바깥의 OS 시스템 푸시를 사용하므로 전용 화면 디자인이 필요하지 않다, 정책과 문구만 정의한다"고 세 행 모두에 못박았다.

## 종류

| ID | 기능 | 발송 주체 | 착지점 |
|---|---|---|---|
| `P-01` | 토핑 등록 알림 | 서버 이벤트 (C-106 배치 확정 저장) | `G-002` → `C-001` |
| `P-02` | 오전 리마인드 | 스케줄러 10:00 KST | `G-001` |
| `P-03` | 저녁 리마인드 | 스케줄러 20:00 KST | `G-001` |

## P-01 발송 규칙 (이벤트 기반)
- **발송 시점**: 그룹원이 `C-106`에서 [[토핑]] 배치를 **확정 저장한 시점**.
- **수신 대상**: **본인을 제외한 전체 그룹원**에게 **개별 발송**.
- **묶음·상한·쿨다운 없음.** 토핑 1개당 알림 1건이 그대로 나간다. 12명이 연속으로 쌓으면 그만큼 발송된다.
- **착지 분기**: 그룹 권한 유효 → `C-001`, 권한 없음·그룹 삭제 → `G-001` + 토스트.

## P-02·P-03 발송 조건 (스케줄 기반)
- 셋 모두 충족해야 발송: **가입 그룹 1개 이상** + **알림 권한 허용** + **유효 토큰 보유**.
- 두 알림의 조건은 동일하고 시각만 다르다(10:00 / 20:00 KST). 마감 시각 03시와는 별개 스케줄이다 → [[캔버스-마감-스케줄]].

## 권한 프라이밍
- 권한 요청은 푸시 화면이 아니라 **그룹 합류 지점**에서 일어난다 — `A-004`(그룹 참여)·`A-005`(새 그룹 생성)의 시스템 동작 말미에 **프라이밍 모달 1회 노출**이 붙어 있다.
- 프라이밍에서 **"나중에"를 고르면 OS 다이얼로그를 호출하지 않고, 재노출도 없다.** 즉 프라이밍은 진입당 1회가 아니라 **생애 1회**에 가깝다.

## 딥링크 생명주기
푸시를 탭해 들어오는 경로는 [[스플래시-애니메이션|A-001]]이 관장한다.
- **소비 조건**: 토큰이 유효하고 딥링크를 보유한 경우에만 **세션에 저장 후 1회 소비**.
- **폐기 조건**: 미로그인 상태 / 강제 업데이트 대상. 폐기되면 로그인을 마쳐도 딥링크 목적지가 아니라 **일반 진입(`G-001`)** 으로 떨어진다.
- 유효시간은 **당해 세션 한정**이다.

## 토큰 생명주기
- **탈퇴(S-003)**: 계정·데이터는 soft delete이지만 **푸시 토큰만 즉시 하드 삭제**한다. 보존 정책이 갈리는 유일한 데이터다.
- **로그아웃(S-005)**: 즉시 삭제. 재로그인 시 다시 등록한다.

## 미결
- **알림 문구가 한 줄도 정의되지 않았다.** 원본이 "정책과 문구만 정의한다"고 적었으나 정작 문구는 세 행 모두 비어 있다 → [[open-questions]]
- **P-01 예외 케이스 프레임 미확인** — 원본이 "푸시알림 예외케이스 코드 E-04 / E-07 프레임이 캔버스 페이지에 존재 (상세 내용 확인 필요)"로 스스로 미확인 표기했다 → [[open-questions]]

## 연관
- [[토핑]] — P-01의 발송 트리거(C-106 배치 확정).
- [[그룹]] — 발송 대상 범위와 권한 유효성 판정 단위.
- [[캔버스-마감-스케줄]] — 같은 스케줄러 계열이나 시각(03시)과 목적이 다르다.
- [[스플래시-애니메이션]] — 딥링크 소비·폐기가 일어나는 지점(A-001).
