# Nametag-Chip (프로필·닉네임 컬러 규칙)

[[협업-캔버스-앱]]에서 유저를 표현하는 **닉네임 첫 글자가 들어간 원형 프로필 이미지**. 유저 타입(12종)이 여러 UI 요소의 텍스트 컬러를 강제 결정하는 기준. S-101(그룹 사이드 메뉴)에서 다른 유저를 볼 때 노출. **타입→컬러 매핑은 요소별로 별개**다: 토스트 닉네임([[S-101-프로필-닉네임-컬러-규칙-v0.4]])과 Grouptag-Chip Timestamp([[S-101-프로필-이미지-및-그룹칩-내-타임스탬프-컬러-규칙-v0.1]])는 Cherry 계열 단계가 서로 다름(같은 값이어야 하는 규칙 아님).

## 구성
- **6개 컬러**(연핑크·진핑크·체리·그레이·멜론·푸딩) × **각 2타입** = **총 12종**.
- 계정당 **12종 중 1종 랜덤** 배정.
- 이와 별개로 **Default 상태**가 있다(v0.4 신설, 아래 절). 랜덤 배정 대상이 아니라 **타입을 결정할 수 없을 때의 폴백**이므로 12종 안에 들어가지 않는다.

> ⚠️ 2026-07-18 TJYG-Android 구현(`YGColorChipType`)과 상충 — 코드는 `NametagChip1`~`NametagChip13`(13종) + `NametagChipPlus`로 정의돼 **정책 12종과 개수 불일치**. `NametagChipPlus`는 2026-07-31 구현 갱신에서 **멤버 5명 이상일 때의 "+" 집계 칩**(색 타입 아님)으로 확정 → 쟁점은 정책 12종 vs 코드 13종. → [[open-questions]] 등록. 구현 측(Android) 추적은 해당 플랫폼 구현 문서의 open-questions([2026-07-18])에 교차 기록.
> **2026-08-31 단서**: [[S-101-프로필-닉네임-컬러-규칙-v0.4]]가 Default 상태를 신설하면서 **12종 + Default = 13**이 됐다. 코드 13종이 이 Default를 한 항목으로 흡수한 결과일 가능성이 있으나, 정책은 Default를 랜덤 배정 타입으로 취급하지 않으므로 **가설일 뿐 해소는 아니다**.

## 컬러 매핑 (요소별 별개 — 상충 아님)

타입→컬러 매핑은 **UI 요소마다 별개 표**를 쓴다. 그레이/멜론/푸딩은 두 표 동일, **Cherry 계열만 단계가 다름**.

### ① 토스트 닉네임 텍스트 ([[S-101-프로필-닉네임-컬러-규칙-v0.4]])
공용 캔버스 액션 발생 시 동접 그룹원에게 뜨는 토스트의 **닉네임 텍스트** 컬러.

| 컬러 (타입) | 텍스트 컬러 |
|---|---|
| 연핑크 (Type 1, 2) | Cherry-200 |
| 진핑크 (Type 3, 4) | Cherry-300 |
| 체리 (Type 5, 6) | Cherry-400 |
| 그레이 (Type 7, 8) | White |
| 멜론 (Type 9, 10) | Melon |
| 푸딩 (Type 11, 12) | Pudding |
| **Default** | **미명시** — 원문에 토큰 이름 없음, 예시 이미지상 회색 계열 → [[open-questions]] |

### ② Grouptag-Chip Timestamp 텍스트 ([[S-101-프로필-이미지-및-그룹칩-내-타임스탬프-컬러-규칙-v0.1]])
G-001에서 그룹 대표 토핑과 노출되는 Grouptag-Chip의 **Timestamp 텍스트** 컬러. 기준 = 해당 그룹에서 **마지막으로 변화를 가한**(토핑 추가·편집, 배경 추가·변경) 유저의 타입.

| 컬러 (타입) | 텍스트 컬러 |
|---|---|
| 연핑크 (Type 1, 2) | Cherry-100 |
| 진핑크 (Type 3, 4) | Cherry-200 |
| 체리 (Type 5, 6) | Cherry-300 |
| 그레이 (Type 7, 8) | White |
| 멜론 (Type 9, 10) | Melon |
| 푸딩 (Type 11, 12) | Pudding |

> 같은 자리를 Gray-200으로 준다(나머지 5행은 일치). Android 구현

## 타입 고정 정책 (v0.2 추가, v0.3 유지)
- 타입은 **계정 생성 시 1회 랜덤 배정**, 이후 변경 없음.
- **동일 닉네임이라도 계정이 다르면 서로 다른 타입** 가능.
- 배정 타입은 모든 화면에서 동일 유지, 앱 재접속·그룹 변경에도 불변. 별도 타입 변경 기능 없는 한 계정 유지 동안 동일 타입.
- 예: 계정 A(닉네임 `홍씨`) → Type 1 고정, 계정 B(닉네임 `홍씨`) → Type 8 고정. 닉네임 같아도 계정 다르면 컬러 다름.

## Default 상태 (v0.4 현행, [[S-101-프로필-닉네임-컬러-규칙-v0.4]])

12종 중 하나를 **정상 결정할 수 없을 때** 노출하는 폴백. 원문 표현은 "Nametag-Chip에 문제 생기면 다 Default로 노출"이라 아래 2건은 **열거가 아니라 예시**이고, 규칙 자체는 포괄적이다.

- **탈퇴한 그룹원**의 Nametag-Chip을 노출해야 하는 경우.
- Nametag-Chip **불러오기에 실패한 경우**.

표현(예시 이미지 기준):

| 요소 | Default 표현 |
|---|---|
| Nametag-Chip | 닉네임 첫 글자 대신 **`-`(대시) 글리프** |
| Toast > Username | `{닉네임}님이` 대신 **`알 수 없는 사용자가`** (예: `알 수 없는 사용자가 59분 전에 쌓았어요`) |
| Grouptag-Chip | 닉네임 자리에 **`알수없음`** (예: `알수없음  59분전`) |

- **C-202와의 관계**: [[토핑-spotlight]](C-202)가 이미 탈퇴 유저 Toast를 `알 수 없는 사용자가 …`로 규정했다. v0.4는 그 문구를 재확인하면서 규칙을 **칩 그래픽까지** 넓힌 것이다 — 상충이 아니라 확장.
- **이름 충돌 주의**: C-202 Spotlight의 `Default` 상태(모든 토핑이 동일 레벨)와는 **다른 개념**이다. 그쪽은 화면 상태, 이쪽은 프로필 칩의 폴백 표현이다.
- ⚠️ [2026-08-31] Default의 **컬러 토큰**과 **Grouptag-Chip `알수없음`의 관할 문서**가 미확정 → [[open-questions]]
