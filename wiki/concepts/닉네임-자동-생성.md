# 닉네임 자동 생성

[[협업-캔버스-앱]]에서 **계정 생성 시 시스템이 닉네임을 1회 부여**하는 규칙. 사용자가 입력하는 [[이름-입력-규칙]](유효성)과는 **별개 층위**다 — 이건 시스템 부여, 저쪽은 입력 검증이고 **자동 생성물은 유효성 검사를 거치지 않는다.**

## 생성 규칙 (v0.1 현행, [[S-002-앱-닉네임-생성-정책-v0.1]])
- **시점**: 계정 생성 시 **1회**.
- **조합**: `형용사/동사` 1개 + `파르페 재료` 1개 → `{형용사/동사}{재료}` **공백 없이 붙여쓰기**.
  - 예: `녹는딸기`, `몽글한푸딩`, `스며드는블루베리`, `말랑한커스터드`, `톡톡튀는스프링클`, `단카라멜`.
- **저장·불변**: 계정 생성 즉시 **DB 저장**, 이후 **재계산하지 않는다**(재렌더링 시 재추첨 금지).
- **적용 순서**: 계정 생성 = 생성 규칙 우선 → **사용자가 수정하는 시점부터** [[이름-입력-규칙]] 적용.

## 앱 ↔ 그룹 값 공유 (v0.1 현행, [[S-102-그룹-닉네임-생성-정책-v0.1]])
- 앱 닉네임과 그룹 내 닉네임의 **초기값은 동일 로직·동일 결과값**. 계정 생성 시 만든 **1개 값을 재사용**한다.
- **그룹마다 재추첨하지 않는다** — 여러 그룹에 속해도 최초 닉네임은 전부 같다.
- 미결: 앱 닉네임을 나중에 수정했을 때 기존 그룹 닉네임이 **따라 바뀌는지(연동) / 최초 1회 복사 후 독립인지** 미규정 → [[open-questions]].

### 길이 상한 검증
풀 실측: 형용사 최장 `바스락거리는`(6자), 재료 최장 `슈가파우더`(5자) → **조합 결과 최대 11자**, 최소 3자(`단`+`딸기`). [[이름-입력-규칙]]의 **15자 상한 안에 구조적으로 갇힌다** — 자동 생성물이 유효성 검사를 안 거쳐도 상한을 넘을 수 없다.

## 다른 "랜덤"과의 구분
> G-001에는 수명이 다른 랜덤이 여럿이다. 뭉뚱그리면 구현이 틀어진다.
> - **닉네임 자동 생성** = 계정 생성 시 1회, DB 저장 후 영구 고정.
> - **[[토핑]] 템플릿 그래픽**(6종) = 그룹별 최초 1회 부여, **첫 토핑 등록 전까지** 고정.
> - **[[토핑]] 변형 타입**(`Left/Right-1~3`) = **목록 조회 응답마다 재추첨**.
>
> 원문도 이 구분을 명시한다 — 토핑 회전은 매 렌더 동일 결과가 필요해 렌더 시점 난수를 금지하지만, 닉네임은 1회 부여 후 고정값이라 난수 소스 제약이 다르게 걸린다.
