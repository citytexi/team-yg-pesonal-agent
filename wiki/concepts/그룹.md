# 그룹

[[협업-캔버스-앱]]의 협업 단위. 그룹마다 캔버스·멤버·닉네임을 가진다.

## 생성 / 참여
- **생성** (A-005): 그룹명 입력 → 초대 코드 자동 발급, 생성자가 그룹장 등록.
- **참여** (A-004): 초대 코드 입력 → 그룹 합류.
- 최대 인원 **12명** 고정. MVP에서 그룹명·인원수 추후 변경 불가.
- **그룹 진입**: 중간 화면 **G-002**가 [[기능정의서-v6]]에서 삭제됐다가 [[기능정의서-v7]]에서 **복원**됐다. 현행은 A-004(→ A-006 닉네임 입력)·A-005 완료 후 **G-002를 거쳐 C-001**로 간다. G-002가 담당하는 **"그룹 권한 유효 여부"** 분기도 함께 돌아와, v6에서 생겼던 권한 검증 위치 미결이 종결됐다.
- **참여·생성의 시작점 변경(v7)**: A-004·A-005의 진입 경로가 `A-003`(약관 동의) → **`G-001`**(그룹 목록)로 바뀌었다. 약관 동의 직후가 아니라 그룹 목록에서 참여·생성을 시작한다.
- **푸시 권한 프라이밍**: A-004·A-005 완료 시점에 **프라이밍 모달 1회**가 뜬다. "나중에"를 고르면 OS 다이얼로그를 호출하지 않고 재노출도 없다 → [[푸시-알림-정책]].

## 그룹명 입력 정책 (A-005, v0.1, [[A-005-그룹명-정책-v0.1]])
- **허용 문자**: 한글·영문·숫자·공백(스페이스바)만. 특수문자·이모지 불가.
- **글자 수**: 최소 1자 ~ 최대 10자. 글자 사이 공백도 1글자로 카운트.
- **공백**: 맨 앞·맨 뒤 불가. 중간 공백 1칸만 허용, 연속 공백 불가.
- 통과 `홍 길동` / 불통과 `   `·`길동 `·`홍  길동`·10자 초과.
- 닉네임 정책과 규칙 구조 동일, **상한만 다름(그룹명 10자 / 닉네임 15자)**. 공통 규칙 → [[이름-입력-규칙]].

## 닉네임
- 그룹 내 닉네임은 [[기능정의서-v4]]부터 가입 시 입력(A-004/A-005), 수정은 S-102.
- 캔버스 객체에 작성자 닉네임 표시(C-202) — 타인 토핑 탭 시 [[토핑-spotlight|Spotlight]] + 작성자 [[toast|Toast]]. 탈퇴 유저는 "알 수 없음"(예: `알 수 없는 사용자가 59분 전에 쌓았어요`).
- **닉네임 입력 유효성 규칙 확정** → 공통 정리는 [[이름-입력-규칙]]. 핵심: 한글·영문·숫자·공백만, **최대 15자**(공백 포함 카운트), 앞뒤 공백 불가·중간 1칸·연속 공백 불가.
  - **그룹 내 닉네임** = S-102([[S-102-닉네임-정책-v0.2]]), **앱 닉네임** = S-002([[S-002-앱닉네임-정책-v0.2]]). 둘 다 규칙 동일(15자), 화면만 다름 — 화면 분기 대비해 문서는 따로 유지.
- **초기 닉네임은 입력이 아니라 부여** — 계정 생성 시 1회 만든 값을 앱 닉네임과 **최초 그룹 진입 시 닉네임에 공통 재사용**한다. **그룹마다 재추첨하지 않으므로** 여러 그룹에 속해도 초기 닉네임이 같다. 생성 규칙·조합 풀 → [[닉네임-자동-생성]]. (앱 닉네임 수정 시 기존 그룹 닉네임 연동 여부는 미결 → [[open-questions]])
  - 그룹명은 상한만 다름(10자, [[A-005-그룹명-정책-v0.1]]).
  - **금칙어·그룹 내 중복**은 [[기능정의서-v7]]에서 확정됐다 — **중복 허용**(12명 전원 동일 닉네임 가능)·**금칙어 없음** → [[이름-입력-규칙]].
  - **A-006(그룹 참여 중 닉네임 입력)**이 v7에서 신설돼, 참여 흐름 안의 닉네임 입력 지점이 별도 화면으로 분리됐다.

## 목록 노출 (G-001)
- **조회**: 한 번의 API 호출로 전체 조회, 페이지네이션 없음 ([[G-001-무한파르페-정책설계-v0.3]]).
- **조회 필드**: 그룹ID·프리뷰 이미지(대표 [[토핑]])·이름·활동 시간.
- **화면 노출**: 그룹 이름(라벨 칩), 대표 토핑, 상대 활동 시간. 그룹ID는 조회하되 화면 미표시.
- 미노출: 인원/최대인원수, 참여 인원 ([[기능정의서-v5]] 기준).
- **정렬**: **활동순 확정**(자주 보는 그룹 상단, [[G-001-무한파르페-정책설계-v0.3]]). 동률 시 그룹 생성일시 최신순(v0.3 타이브레이크). 구 "가입순/이름순 투표 선택지"는 소멸.
- **레이아웃/새로고침/나가기 반영**: [[무한-파르페-그리드]] 참고 (지그재그 배치 — 행당 1개 좌/우 교차, Pull-to-Refresh 전체 교체, 나가기 시 패턴 재계산).

## 나가기·탈퇴 (v7 확정)
- **그룹 나가기(S-103)**: 남은 그룹원이 **있으면 그룹 유지**, **마지막 1인이 나가면 그룹과 캔버스 전체 삭제**. 그룹의 수명이 멤버 수 0에 묶였다.
- **내 토핑은 익명화 보존**된다 — 나가도 지워지지 않고 작성자 표시만 사라진다. 캔버스는 남는 사람들의 것이므로 기록을 깨지 않는다. 표시는 [[nametag-chip]] Default 타입 + `알 수 없음` → [[토핑-spotlight]].
- **서비스 탈퇴(S-003)**: 탈퇴 안내 → **가입 그룹 자동 탈퇴** → 계정·데이터 **soft delete** → 앱 종료. 재가입 시 새 유저로 취급한다.
  - **푸시 토큰만 soft delete 대상이 아니라 즉시 하드 삭제**한다 → [[푸시-알림-정책]].

## 그룹 신고 (S-104)
- 신고 버튼 탭 → **접수 안내 토스트** → 팀이 내용을 검토하고 조치. v6까지 "MVP는 공버튼(비활성 또는 추후 출시 안내)"이던 것이 v7에서 동작하는 기능이 됐다.

## 그룹장
- [[기능정의서-v3]]에서 **그룹장 기능 삭제** 결정. 이후 그룹장 권한 이양/그룹 삭제 정책은 축소·미결.
- v7의 "마지막 1인 이탈 시 그룹 삭제"가 사실상 그룹 소멸 규칙을 대신한다 — 삭제 권한을 가진 사람이 없고, 멤버 수가 0이 되는 것이 유일한 삭제 경로다.
