# S-002 앱닉네임 정책 (생성 정책 v0.1)

- **원본**: `raw/S-002-앱-닉네임-생성-정책-v0.1.md`
- **날짜**: 미기재 (2026-07-29 수집). 작성자 미기재
- **도메인**: product
- **역할**: **앱 닉네임 초기 자동 생성**의 정본. **조합 풀 실물을 담은 유일한 소스.**
- **판본 관계 없음** — 기존 유효성 정본([[S-102-닉네임-정책-v0.2]]·[[S-002-앱닉네임-정책-v0.2]])을 대체하지 않는다. 이 문서 §2~3(유효성·예시)은 그 문서들의 **중복 전재**이고, 고유 내용은 §1(생성)뿐이다.

## 핵심 요점
- **생성 시점**: 계정 생성 시 **1회**. `{형용사/동사}{재료}` **공백 없이 붙여쓰기** (`녹는딸기`, `몽글한푸딩`).
- **저장·불변**: 계정 생성 즉시 **DB 저장**, 이후 **재계산하지 않음**(재렌더링 시 다시 뽑지 않음).
- **난수 제약이 G-001 토핑 회전과 다름**(원문이 명시적으로 구분): 토핑 회전은 매 렌더마다 같은 결과가 나와야 해 렌더 시점 난수를 금지하지만, 닉네임은 **1회 부여 후 고정값**이라 난수 소스 제약이 다르게 적용된다.
- **생성 주체 미정** — 원문 `[K2]` 표기. 서버 생성 후 응답 vs 클라이언트 생성 후 업로드. 원문 판단: 계정당 유일성이 필요 없다면(중복 허용) 클라이언트도 가능하나 **어뷰징·치우침 방지 관점에서 서버 생성 권장**. → [[open-questions]]
- **조합 풀 = 형용사/동사 100 × 파르페 재료 30 = 3000 조합.** 실물 목록은 원문 §1.2 (위키 전재는 [[닉네임-자동-생성]]).
- 원문 예시: `스며드는`+`블루베리`, `말랑한`+`커스터드`, `톡톡튀는`+`스프링클`, `단`+`카라멜`.
- §2~3 유효성·입력 예시는 기존 문서와 **문자 그대로 동일**(허용 문자·1~15자·공백 규칙, 통과/불통과 4케이스).
- §4 적용 범위: 그룹 내 닉네임 = 유효성 규칙만 / 앱 닉네임 = 생성 규칙 우선 후 수정 시점부터 유효성.
- 개인정보: 예시가 이미 더미(`홍 길동`), 작성자 미기재 → 마스킹 대상 없음.

## 해소한 미결
- **조합 단어 목록 미수집**([[open-questions]] 2026-07-29) → **해소.** 풀 전문을 이 문서가 싣는다.
- **자동 생성물이 15자를 넘는가**([[open-questions]] 2026-07-29) → **해소(구조적으로 불가).** 풀 실측 — 형용사 최장 `바스락거리는`(6자) + 재료 최장 `슈가파우더`(5자) = **최대 11자**, 최소 `단`+`딸기`류 = 3자. 상한 15 안에 갇힌다.

## 미해결 (→ [[open-questions]])
- ⚠️ **`[K2]` 생성 주체(서버 vs 클라이언트)** 미확정.
- ⚠️ **작성일·작성자·버전 표기 없음** — 기존 닉네임 문서들과의 시간 순서를 문서 자체로는 판정할 수 없다(내용 포함관계로만 후속 추정).
