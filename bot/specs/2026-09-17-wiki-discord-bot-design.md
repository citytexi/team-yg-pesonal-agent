# 위키 질의응답 디스코드 봇 설계

- 작성일: 2026-09-17
- 상태: 설계 확정 (구현 전)
- 범위: 이 저장소의 `wiki/`를 근거로 디스코드에서 질문에 답하는 읽기 전용 봇

## 1. 목적

Mash-Up 팀원이 디스코드에서 제품 정책을 물으면, 이 저장소의 정책 지식 위키를 근거로
답하는 봇을 만든다. 디자이너·기획자·iOS 개발자처럼 저장소를 직접 열지 않는 사람도
현행 정본이 무엇인지 확인할 수 있게 하는 것이 목표다.

봇은 답변만 한다. 위키를 고치거나 소스를 추가하지 않는다.

## 2. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 주 업무 | 위키 질의응답(읽기 전용) | 쓰기 흐름은 PR·승인 절차가 필요해 별도 과제로 미룬다 |
| 사용자 | 팀원 전체 | `wiki/personal-private/`도 팀원 이름 수준이라 제외하지 않는다 |
| 근거 범위 | `wiki/` 우선, 부족분만 해당 소스 페이지가 가리키는 `raw/` | `raw/`를 자유 검색하면 폐기본을 현행 규칙으로 오독한다 |
| 호출 | 멘션으로 시작, 쓰레드에서 되물음 | 맥락 질문("그럼 C-102는?")이 가능해진다 |
| 엔진 | 구독 기반 `claude` CLI 헤드리스 | API 과금을 쓰지 않는다는 사용자 결정 |
| 실행 위치 | 사용자 맥에서 시작, 이후 이전 가능 | 머신 선택을 설정값으로 분리한다 |
| 코드 위치 | 이 저장소의 `bot/` | 위키가 바뀔 때 봇도 같은 PR에서 고칠 수 있다 |

`bot/`이 생기면서 저장소는 `raw/`·`wiki/`·`parfait/`에 이어 네 번째 축을 갖는다.
루트 `CLAUDE.md`에 이 축을 추가해야 한다.

## 3. 채택하지 않은 접근

**상주 세션 하나에 모든 질문을 밀어넣는 방식**은 두 번째 질문부터 빨라지지만, 서로 다른
쓰레드의 대화가 한 세션에 섞이고 컨텍스트가 차면 압축이 일어나 앞선 근거가 흐려진다.

**GitHub Actions에서 `claude`를 실행하는 방식**은 상시 머신이 필요 없다는 장점이 있으나,
구독 토큰을 Secret에 넣어야 하고 이 저장소는 public이라 위험이 크다. 시작 지연도 수십 초
더 붙는다.

## 4. 왜 `claude` CLI를 엔진으로 쓰는가

이 저장소의 실질적 자산은 위키 문서 자체가 아니라 `wiki/conventions.md`가 규정한 읽는
순서와 판정 규칙이다. 구체적으로 다음 네 가지다.

1. 읽는 순서는 `index.md` → `concepts/`·`entities/` → `open-questions.md` → 필요 시 `sources/`다.
2. 판본 판정은 부정 매칭이다. `status: current`가 아닌 모든 소스는 현행 근거가 아니다.
3. `⚠️` 마커가 붙은 조항은 확정 대기 상태이며 근거로 인용하면 안 된다.
4. 같은 용어가 맥락에 따라 다른 규격을 갖는다(동음이의). 맥락 분리는 concept 페이지가 담당한다.

작업 디렉토리를 저장소 루트로 두고 `claude`를 실행하면 `wiki/CLAUDE.md` 스키마와 `query`
스킬이 자동으로 걸리므로, 이 규칙들을 봇 쪽에 다시 구현하지 않아도 된다. 임베딩 기반
검색을 붙이는 대안은 이 규칙들을 전부 잃는다.

## 5. 구조

봇을 네 조각으로 나눈다. 각 조각은 하나의 일만 하고, 나머지를 몰라도 이해되고 시험된다.

### 5.1 `discord-gateway`

discord.js로 게이트웨이에 붙어 멘션을 받고, 쓰레드를 열고, 답을 올린다. 디스코드 규격만
아는 층이다. 위키도 `claude`도 모른다.

이 층은 최대한 얇게 유지한다. 판단 로직이 쌓이기 시작하면 아래 두 조각으로 내린다.

### 5.2 `claude-runner`

질문 문자열과 세션 ID를 받아 `claude` 프로세스를 띄우고 답변 텍스트를 돌려준다. 인자
구성, 시간 초과, 프로세스 정리를 담당한다. 디스코드를 모르므로 터미널에서 단독으로
시험할 수 있다.

`claude` 바이너리 경로를 주입받게 만든다. 시험에서 가짜 스크립트로 바꿔 끼우기 위해서다.

### 5.3 `session-store`

디스코드 쓰레드 ID와 `claude` 세션 UUID의 대응을 보관한다. 봇이 재시작돼도 쓰레드
되물음이 이어지도록 JSON 파일 한 장에 쓴다. 네 조각 중 상태를 갖는 유일한 조각이다.

만료는 7일로 둔다. 그보다 오래된 쓰레드는 새 세션으로 시작한다.

### 5.4 `rate-limiter`

동시 실행 수, 사용자당 분당 질문 수, 하루 총 질문 수를 센다. 시계를 주입받는 순수한
계산 모듈로 만들어 시간 경계를 시험할 수 있게 한다. 한도 초과 시 거절 사유를 돌려주고,
게이트웨이가 그 사유를 그대로 팀원에게 전한다.

## 6. 호출 규격

```
claude -p "<질문>"
  --session-id <uuid>            # 첫 질문. 되물음은 --resume <uuid>
  --permission-mode dontAsk
  --disallowed-tools Bash Edit Write NotebookEdit WebFetch
  --output-format json
```

프로세스의 작업 디렉토리를 저장소 루트로 지정해 실행한다. `--add-dir`은 필요 없다.

**`--restricted`는 쓰지 않는다.** 2026-09-17 실측에서 `--restricted`를 붙이면 `query`·
`ingest`·`lint` 스킬이 전부 로드되지 않았고, 빼면 전부 로드됐다. 이 봇의 가치는 4절에
적은 위키 운영 규약을 스킬로 물려받는 데 있으므로 `--restricted`를 포기하고
`--disallowed-tools`로 개별 차단한다.

`--output-format json`의 출력에서 쓰는 필드는 네 개다.

| 필드 | 용도 |
|---|---|
| `result` | 답변 본문 |
| `session_id` | 되물음에 쓸 세션 ID |
| `is_error` | 실패 판정 |
| `subtype` | 성공 시 `success` |

## 7. 데이터 흐름

### 7.1 첫 질문

1. 게이트웨이가 메시지를 받고 자기 멘션인지 확인한다.
2. 원 메시지에 쓰레드를 연다. 쓰레드 이름은 질문 앞 80자를 잘라 쓴다(디스코드 상한은 100자).
3. 쓰레드에 "찾는 중" 임시 메시지를 올리고 타이핑 표시를 켠다.
4. `session-store`에서 쓰레드 ID를 찾는다. 없으면 새 UUID를 만들어 저장한다.
5. `claude-runner`가 프로세스를 띄우고 stdout의 JSON에서 결과 텍스트를 꺼낸다.
6. 임시 메시지를 답변으로 바꾼다.

3번이 필요한 이유는 응답이 30초에서 2분 걸리기 때문이다. 무반응 구간이 길면 팀원이
봇이 죽은 것으로 오해한다.

### 7.2 되물음

쓰레드 안의 새 메시지는 멘션이 없어도 처리한다. `session-store`에 이미 UUID가 있으므로
`--resume`으로 이어간다. 봇 자신의 메시지는 건너뛴다.

## 8. 답변 형식

본문 뒤에 근거를 분리해 붙인다.

```
G-001 파르페 토핑 인셋은 좌우 4입니다. 같은 side 갭은 -12이고,
Left 좌표는 268·416·564, Right는 354·502·650입니다.

— 근거
· G-001-무한파르페-간격-정책-v0.3 (현행 정본, 2026-07-27)
· 무한-파르페-그리드
```

근거를 분리하는 이유는 `conventions.md`가 현행 정본이 아닌 소스의 인용을 금지하기
때문이다. 판본 상태를 답변 표면에 드러내면 팀원이 구판본 인용을 바로 알아챌 수 있다.

근거에는 위키 페이지 이름만 적는다. GitHub 링크는 `wiki/personal-private/`가 private
submodule이라 그쪽 페이지에서 깨지므로 v1에서 제외한다.

길이 처리는 디스코드 한 메시지 2000자 제한에 맞춰 나눈다. 임베드는 4096자까지 담기지만
표 서식이 깨지므로, 일반 메시지를 코드블록 경계를 지키며 분할한다.

## 9. 안전장치

### 9.1 쓰기 차단

`--disallowed-tools Bash Edit Write NotebookEdit WebFetch`로 쓰기와 명령 실행 도구를
제거한다. 여기에 더해 `claude` 실행 직후 `git status --porcelain`을 확인해 작업 트리가
더러우면 로그에 경고를 남긴다. 값이 싸고, 도구 차단이 뚫렸을 때 알아챌 수 있는 유일한
지점이다.

`--restricted`를 쓰지 않으므로 도구 차단은 `--disallowed-tools` 한 줄에 전부 걸려 있다.
이 인자를 고칠 때는 `Bash`가 빠지지 않았는지 반드시 확인한다.

### 9.2 접근 제한

길드 하나와 채널 화이트리스트에만 응답한다. 봇이 다른 서버에 초대돼도 동작하지 않는다.

### 9.3 사용량 제한

봇은 소유자 한 명의 구독 한도 위에서 돈다. 한도 소진이 조용히 일어나면 소유자의 개인
작업이 예고 없이 막히므로, 세 층으로 막는다.

| 항목 | 초기값 | 설정 키 |
|---|---|---|
| 동시 실행 프로세스 | 2 | `MAX_CONCURRENT` |
| 사용자당 분당 질문 | 2 | `RATE_PER_USER_PER_MIN` |
| 하루 총 질문 | 60 | `DAILY_QUOTA` |
| 프로세스 시간 초과 | 5분 | `TIMEOUT_MS` |

하루 한도를 넘기면 봇이 "오늘 한도를 다 썼습니다"라고 답하고 프로세스를 띄우지 않는다.
동시 실행 한도를 넘긴 요청은 큐에 넣고 순서를 알린다.

## 10. 오류 처리

| 상황 | 처리 |
|---|---|
| `claude` 비정상 종료 | 쓰레드에 한 줄만 안내. 전체 내용은 파일 로그 |
| 시간 초과 | 프로세스를 죽이고 질문을 좁히라고 안내. 세션 UUID는 store에서 삭제 |
| `--resume` 실패 | 새 세션으로 자동 강등. "이전 맥락이 끊겨 새로 시작합니다"를 덧붙임 |
| 봇 재시작 | 진행 중이던 질문은 유실. 시작 시 미완 쓰레드에 끊김을 알림 |
| 답변이 빈 문자열 | 실패로 간주하고 비정상 종료와 같이 처리 |

스택이나 원문 오류를 채널에 뿌리지 않는다. 팀원에게 쓸모가 없고 로컬 경로가 노출된다.

`--resume` 실패를 조용히 새 세션으로 넘기면 팀원이 되물음이 먹힌 줄 착각하므로, 반드시
알린다.

봇 재시작 시 진행 중이던 질문의 복구는 작업 큐 영속화를 요구해 구조가 커진다. 유실을
인정하는 쪽을 택한다.

## 11. 테스트 전략

TDD로 구현한다. 조각마다 시험 방법이 다르다.

**`claude-runner`** — `claude` 바이너리 경로를 주입받게 만들고, 시험에서는 고정된 JSON을
뱉는 가짜 스크립트를 넣는다. 인자 구성, 시간 초과 처리, JSON 파싱, 비정상 종료 코드를
실제 과금 없이 확인한다.

**`session-store`** — 임시 디렉토리에 파일을 쓰고 읽는다. 신규 생성, 재사용, 만료, 손상된
파일 복구를 확인한다.

**메시지 분할** — 순수 함수다. 정확히 2000자, 코드블록에 걸친 경계, 아주 긴 한 줄을 경계
사례로 잡는다.

**사용량 제한** — 순수 함수 더하기 시계 주입으로 만든다. 분당 한도와 하루 한도의 경계,
자정 넘김을 확인한다.

**`discord-gateway`** — discord.js를 흉내 내는 비용이 크므로 실제 디스코드 서버에서 수동으로
확인한다. 그래서 이 층을 얇게 유지한다.

실제 `claude` 호출을 포함한 통합 시험은 한 건만 두고 기본 실행에서 제외한다. 느리고
구독 한도를 먹는다.

## 12. 설정

`bot/.env`에 둔다. `.gitignore`에 추가한다. 이 저장소는 public이므로 토큰이 커밋되면
즉시 폐기해야 한다.

| 키 | 설명 |
|---|---|
| `DISCORD_TOKEN` | 봇 토큰 |
| `GUILD_ID` | 응답할 길드 |
| `ALLOWED_CHANNEL_IDS` | 응답할 채널 목록 |
| `REPO_ROOT` | `claude`를 실행할 저장소 경로 |
| `CLAUDE_BIN` | `claude` 실행 파일 경로 |
| `MAX_CONCURRENT` / `RATE_PER_USER_PER_MIN` / `DAILY_QUOTA` / `TIMEOUT_MS` | 9.3 참고 |

`bot/.env.example`에 키 목록과 설명을 두고 커밋한다.

## 13. 미해결

- **구독 계정 공유** — 구독 계정 하나를 봇으로 팀 전체가 쓰는 형태는 Anthropic 사용
  정책에서 계정 공유로 해석될 여지가 있다. 사용자가 위험을 인지하고 진행하기로 했다.
- **상시 머신** — 사용자 맥에서 시작한다. 맥이 잠들면 응답이 멈춘다. Oracle Cloud
  Always Free ARM 인스턴스가 후보지만 리전 용량 문제로 생성이 실패할 수 있다. 머신
  선택은 설정값으로 분리했으므로 코드 변경 없이 옮길 수 있다.
- **답변 품질** — 스킬과 위키 규약을 물려받아도 답이 맞는지는 실사용으로만 안다. 초기
  운영에서 오답이 나오면 `wiki/CLAUDE.md`의 query 워크플로를 고치는 쪽으로 대응한다.
  봇 코드에 규칙을 심지 않는다.

- **`--restricted`와 스킬 로드의 상호작용** — 2026-09-17 실측으로 해소됐다.
  `--restricted`는 스킬 로드를 막는다. 6절대로 쓰지 않는다.
