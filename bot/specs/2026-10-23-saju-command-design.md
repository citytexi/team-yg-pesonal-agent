# 사주 명령(`!사주`) 설계

- 작성일: 2026-10-23
- 상태: 구현 완료
- 범위: 디스코드 봇에 `@봇 !사주` 명령을 추가해, 봇 호스트에 따로 둔 `saju-manseryeok` 스킬로 사주를 본다

## 1. 목적

팀원이 디스코드에서 봇에게 사주를 물으면 만세력·사주 원국을 계산해 보여 준다. 계산은 봇 소유자가
만든 `saju-manseryeok` 스킬(결정론적 계산 엔진 `saju.py` + 출력 템플릿)이 맡는다.

이 명령은 저장소 문서 질의응답과 성격이 전혀 다르다. 그래서 **문서 질의응답과 섞이지 않게 격리하는
것**이 설계의 중심이다. 격리는 두 방향이다.

- **봇 소유자 쪽 정보가 사주 세션으로 새지 않는다.** 소유자의 `~/.claude/CLAUDE.md`, 프로젝트 메모리,
  이 저장소 문서, 소유자의 다른 세션 기록이 사주 세션의 컨텍스트에 실리지 않는다.
- **팀원의 생년월일시가 문서 질의응답 쪽으로 새지 않는다.** 사주 스레드의 대화는 저장소를 읽는 세션으로
  넘어가지 않는다.

## 2. 목표 · 비목표 · 반목표

**목표**
- `@봇 !사주`로 사주 스레드를 열고, 그 스레드에서 스킬의 여러 차례 대화(입력 폼 → 확인 → 결과 →
  추가 분석)를 이어 간다.
- 결과는 스킬 템플릿 그대로, 담백한 말투로 낸다.

**비목표**
- 사주 해석의 품질 개선, 스킬 자체의 수정. 스킬은 있는 그대로 쓴다.
- 해외 출생, 1937~2026년 밖의 날짜 지원. 스킬이 지원하지 않으며, 스킬의 오류 메시지를 그대로 전한다.

**반목표** (동작해도 이렇게 되면 실패다)
- 사주 세션에서 저장소 파일, 소유자의 전역 지시문, 메모리, 다른 세션 기록을 볼 수 있다.
- 사주 스레드의 이어지는 질문이 문서 질의응답 세션(저장소를 읽는 세션)으로 들어간다.
- 사주 세션의 `claude`가 셸을 실행하거나 파일을 쓸 수 있다.
- 스킬 파일(코드·템플릿·절기 데이터)이 이 public 저장소에 커밋된다.
- 사주 답변에 봇 페르소나(깔보는 반말)나 밈이 섞인다.

## 3. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 명령 | 본문이 `!사주`로 **시작**하면 사주 명령이다. 뒤에 붙은 내용은 첫 입력으로 넘긴다(`@봇 !사주 1990-05-15 07:30 남 서울`) | `!` 접두어가 일반 질문과 겹치지 않는다. Figma 명령의 "정확히 일치" 규칙은 "figma 코멘트 정책이 뭐야" 같은 질문과 겹쳐서 생긴 것이라 여기는 해당하지 않는다 |
| 스레드 | 채널에서 부르면 새 사주 스레드를 연다. **문서 질문 스레드 안에서 불러도 그 자리에서 이어 가지 않고 새 사주 스레드를 연다** | 한 스레드에 두 종류의 세션이 섞이지 않게 한다 |
| 이어 가기 | 사주 스레드 안에서는 `!사주` 없이 `@봇 …`으로 부르면 사주 세션을 이어 간다. 멘션은 필요하다 | 사용자 결정. 멘션 규칙은 기존 질의응답과 같다 |
| 세션 단위 | 스레드 하나에 세션 하나. 같은 스레드에서만 `--resume` | 스킬이 여러 차례 대화를 전제한다. 질문마다 새 세션이면 폼을 보여 준 사실조차 잊는다 |
| 말투 | 스킬 템플릿 그대로. `PERSONA_DIRECTIVE`·`MEME_DIRECTIVE`를 붙이지 않는다 | 사용자 결정 |
| 스킬 위치 | 봇 호스트의 외부 경로. `.env`의 `SAJU_SKILL_DIR`로 지정한다. 이 저장소에는 넣지 않는다 | 스킬의 해석 데이터·절기 데이터 일부가 네이버 블로그에서 가져온 것이라 재배포 권리가 불분명하다. public 저장소에 한 번 커밋하면 이력에서 지울 수 없다 |
| 엔진 실행 | 봇 안의 MCP 서버가 `saju_calc` 도구 하나만 노출하고, 셸 없이(`execFile`) `saju.py`를 실행한다 | 아래 4절 |

## 4. 접근

세 접근을 검토했고 사용자가 C를 골랐다. 셋 다 `claude`를 빈 디렉토리에서 실행하고 스레드 단위로
세션을 이어 가는 점은 같다. 차이는 `claude`가 `saju.py`를 어떻게 실행하느냐다.

| 접근 | 방식 | 대가 |
|---|---|---|
| A. 좁힌 Bash 허용 | `Bash(python3 <스킬>/scripts/saju.py:*)`만 허용하고 스킬을 원래대로 돌린다 | README가 금지한 Bash 차단을 처음 연다. 경계가 앞쪽 일치 규칙 하나에 달린다. 궁합은 결과 JSON 두 개를 파일로 써야 해서 `Write`까지 열어야 한다 |
| B. 두 단계 분리 | 도구 없는 `claude`가 입력을 JSON으로 정리 → Node가 검증해 `saju.py` 실행 → 두 번째 `claude`가 템플릿에 옮긴다 | 한 턴에 `claude`를 두 번 불러 구독 한도를 두 배로 쓴다. 단계를 잇는 프로토콜 코드가 는다 |
| **C. 전용 도구 하나 (채택)** | 봇 안의 작은 MCP 서버가 `saju_calc` 하나만 노출한다. `claude`의 내장 도구는 전부 끈다 | MCP SDK 의존성이 하나 는다 |

C를 고른 이유: Bash와 파일 쓰기를 열지 않으면서 한 턴에 `claude`를 한 번만 부르고, 스킬의 여러 차례
대화가 그대로 동작한다. 인자가 정해진 칸으로만 들어오므로 셸 문법이 끼어들 자리가 없다.

## 5. 격리 규격

사주용 `claude` 호출은 문서 질의응답 호출과 **인자를 공유하지 않는** 별도 빌더로 만든다.

| 수단 | 막는 것 |
|---|---|
| `cwd` = 봇 전용 빈 디렉토리. **저장소 git 트리 밖**(기본 `os.tmpdir()/teamyg-bot-saju-sandbox`). 트리 안이면 gitStatus와 git 루트 기준 메모리가 실릴 수 있어 시작 시 거부한다 | 저장소 `CLAUDE.md`·문서, 저장소 경로에 묶인 프로젝트 메모리 |
| `--setting-sources ""` | 소유자의 `~/.claude/CLAUDE.md`와 사용자 설정 |
| `--tools ""` | 내장 도구 전부(Read·Grep·Bash·Write·WebFetch 등). 파일을 볼 수도 쓸 수도 없으므로 자동 메모리 기록도 일어나지 않는다 |
| `--strict-mcp-config --mcp-config <saju 전용 설정>` | 소유자에게 설치된 다른 MCP 서버(Notion·Gmail 등) |
| `--allowed-tools mcp__saju__saju_calc` | `--permission-mode dontAsk` 아래에서 도구 승인을 이 하나로 한정 |
| 질문마다가 아니라 스레드마다 새 `--session-id`, 같은 스레드에서만 `--resume` | 다른 스레드와 소유자 개인 세션의 기록 |
| `SECRET_ENV_KEYS` 제거한 env(기존 `withoutSecrets` 재사용) | 디스코드·Figma 토큰 |

**실측 (2026-10-23, 소유자 맥).** 빈 임시 디렉토리에서 `--tools "" --strict-mcp-config
--no-session-persistence`로 실행했을 때, `--setting-sources`를 빼면 `~/.claude/CLAUDE.md`의 cmux·Orca
문단이 컨텍스트에 실렸고, `--setting-sources ""`를 주면 실리지 않았다. 구독(OAuth) 인증은 두 경우 모두
동작했다. 자동 메모리 사용법 안내 문단은 두 경우 모두 실렸다(빈 디렉토리라 실제 메모리 내용은 없다).

**`--bare`는 쓰지 않는다.** CLAUDE.md 자동 탐색과 자동 메모리를 함께 끄는 옵션이지만 인증을
`ANTHROPIC_API_KEY`로만 받는다. 봇은 구독으로 돈다(기존 설계 2절 "엔진").

**세션 기록은 남는다.** `--resume`이 필요하므로 `--no-session-persistence`를 쓸 수 없다. 팀원의
생년월일시는 봇 호스트의 `~/.claude/projects/<샌드박스 경로>/*.jsonl`에 저장된다. 같은 내용은 이미
디스코드 채널에 남아 있다. README에 이 사실을 적는다.

## 6. 구조

```
gateway ──parseCommand──▶ saju 명령 / 사주 스레드 판정
   │
   ▼
handle-saju ──▶ saju-runner (claude, 격리 인자) ──MCP stdio──▶ saju-mcp-server ──execFile──▶ saju.py
   │
   ▼
session-store (사주 전용 파일: 스레드 → sessionId)
```

### 6.1 명령 판정 (`command.js`)

- 본문이 `!사주`로 시작하면 `{ kind: "saju", input: <나머지, trim> }`.
- 그 외는 기존 규칙 그대로(figma 정확 일치 → 그 외 question).

### 6.2 스레드 종류 판정 (`gateway.js`)

**사주 스레드 = 봇이 만든 스레드(`ownerId`가 봇) 이면서 이름이 `🔮 사주`로 시작하는 스레드.** 판정에 저장소
항목을 쓰지 않으므로 세션이 만료돼도 종류는 남는다. 세션은 문서 질의응답과 **다른 파일**
(`SAJU_SESSION_FILE`, 기본 `./data/saju-sessions.json`)의 별도 `session-store`에 둔다. 두 세션이 한
저장소를 공유하지 않으므로 `kind` 필드가 필요 없다(2026-10-23 계획 작성 중 단순화).

| 위치 | 본문 | 처리 |
|---|---|---|
| 채널 | `!사주 …` | 새 사주 스레드 + 새 사주 세션 |
| 사주 스레드 | `!사주 …` | 같은 스레드에서 이어 간다(`!사주` 접두어는 떼고 넘긴다) |
| 사주 스레드 | 그 외 | 같은 사주 세션으로 이어 간다 |
| 문서 질문 스레드 | `!사주 …` | 채널에 새 사주 스레드를 연다. 원래 스레드에는 새 스레드 링크를 짧게 남긴다 |
| 문서 질문 스레드 | 그 외 | 기존 동작 |
| 사주 스레드인데 세션 항목이 만료·유실 | 그 외 | **사주로 이어 간다(새 사주 세션).** 문서 질의응답으로 떨어뜨리지 않는다 |

마지막 줄이 반목표 "사주 질문이 문서 세션으로 들어간다"를 막는 자리다. 이름으로 판정하므로 서버 관리자가
사주 스레드의 이름을 바꾸면 그 스레드는 문서 질문 스레드로 읽힌다. 봇 스레드의 이름을 바꿀 사람은 관리자뿐이라
이 위험은 받아들이고 README에 적는다.

### 6.3 `saju-mcp-server`

stdio MCP 서버. 봇 코드(`bot/src/saju-mcp-server.js`)이고, `claude`가 `--mcp-config`로 띄운다.

- 도구 `saju_calc` 하나. 입력 스키마:
  - `date` (`YYYY-MM-DD`, 필수), `time` (`HH:MM` 또는 `모름`), `gender` (`남`|`여`, 필수),
    `region` (문자열 또는 `모름`), `calendar` (`solar`|`lunar`), `leap` (불리언), `sewoonYear` (정수, 선택)
  - 궁합: `partner` 필드에 같은 모양의 두 번째 사람. 있으면 두 사람을 각각 계산한 뒤, 결과 JSON을
    **서버 전용 임시 디렉토리**에 써서 `--compat A.json B.json`을 실행하고 지운다.
- 값마다 정규식·허용 목록으로 검증한다. 실패하면 도구 오류로 돌려준다(셸로 넘어가지 않는다).
- `execFile(pythonBin, [<스킬>/scripts/saju.py, ...args])`. 셸 없음. 타임아웃.
- `saju.py`의 표준 출력(JSON)을 그대로 돌려준다. `error` 키도 그대로 돌려준다.
- 스킬 경로와 파이썬 경로는 `--mcp-config`의 `env`로 받는다.

### 6.4 시스템 프롬프트

`--tools ""`라 `claude`는 스킬 파일을 읽을 수 없다. Node가 시작할 때 `SAJU_SKILL_DIR`에서 다음 파일을
읽어 `--append-system-prompt`로 싣는다.

- `SKILL.md`, `references/input-normalization.md`, `references/output-template.md`
- `references/reference-data.md`는 싣지 않는다. 엔진이 계산하므로 검토용 표가 필요 없다(약 12KB 절약).

그 앞에 봇 전용 지시를 붙인다.

- 엔진 실행은 `saju_calc` 도구로 한다. 스킬 문서의 `python3 … saju.py` 명령과 `--compat` 파일 인자는
  이 도구 호출로 대신한다.
- 사주와 무관한 질문에는 답하지 않고, 이 스레드는 사주 전용이라고 안내한다.
- 디스코드 메시지로 나간다(마크다운 표가 디스코드에서 깨질 수 있는 점은 7절).

### 6.5 `handle-saju`

`handle-question`과 같은 골격(한도 확인 → 스레드 확보 → 세션 조회 → 실행 → 전송 → 세션 저장)이고,
러너와 세션 저장소만 다르다. 사주 러너가 같은 `ask({ question, sessionId, resume })` 모양을 갖추면
`createQuestionHandler`를 사주 저장소·사주 러너로 한 번 더 만들어 그대로 쓴다.

### 6.6 설계 검토에서 정한 것 (작성자 판단)

- **스레드 안에서 새 사주 스레드 열기.** 디스코드는 스레드 안 메시지로 새 스레드를 시작할 수 없다.
  부모 채널에 시작 메시지 없이 스레드를 만든다(`threads.create`).
- **봇이 연 스레드가 아닌 곳**(다른 사람이 만든 스레드, Figma 스레드)에서 `!사주`를 받으면 문서 질문
  스레드와 같게 처리한다: 새 사주 스레드를 연다.
- **사주 스레드 이름에 입력값을 넣지 않는다.** 생년월일시가 채널의 스레드 목록에 보이면 안 된다.
- **`saju.py` 오류.** 오류가 나면 종료 코드 1로 끝나면서 표준 출력에 `{"error": ...}`를 낸다. MCP
  서버는 종료 코드 1이어도 표준 출력이 JSON이면 그대로 돌려준다. JSON이 아니거나 타임아웃이면 도구
  오류로 돌려준다.
- **`--allowed-tools`는 화이트리스트가 아니다**(`claude-runner.js` 주석, 실측). 이 설계에서는
  `--tools ""`와 `--strict-mcp-config`가 남는 도구를 `saju_calc` 하나로 줄이므로 충돌하지 않는다.
  7절의 실측에서 다른 도구가 노출되지 않는 것까지 확인한다.

## 7. 빌더에게 남긴 것

- 출력 템플릿의 마크다운 표가 디스코드에서 표로 렌더링되지 않는다. 그대로 둘지, 시스템 프롬프트에서
  코드 블록 정렬 등으로 바꾸라고 지시할지. 메시지 분할(`message-split.js`)이 표 중간을 자르지 않는지도
  확인한다.
- MCP SDK(`@modelcontextprotocol/sdk`) 버전 선택과 stdio 서버 구현.
- `--tools ""`일 때도 `--mcp-config`의 도구가 노출되는지, `--allowed-tools mcp__saju__saju_calc`가
  `dontAsk`에서 승인되는지 실측한다.

실측 결과(2026-10-23, `test/claude-live.test.js`, 인자 변경 없이 통과):

- `--tools ""`와 `--mcp-config`를 함께 써도 `saju_calc`는 노출되고, `--allowed-tools
  mcp__saju__saju_calc`가 `dontAsk`에서 승인된다. 1990-05-15 07:30 남 서울 질의에 일주
  경진(庚辰)과 진태양시 보정을 돌려줬다.
- 도구 목록 질의에 모델은 `mcp__saju__saju_calc` 하나만 답했다. `Bash`·`Read`·`Write`는 없다.
- `cmux`·`Orca` 문맥과 브랜치·`Memory Index`·`TEAMYG` 문맥은 답에 나오지 않았다. 다만 두 질의 모두
  모델이 "사주 전용 스레드"라며 질문 자체를 거절했다. 유입이 없다는 증거로는 약하다(부재를 직접 보인 것이
  아니라 시스템 프롬프트 인용 요청을 거절한 것). 인자 빌더 단위 테스트의 격리 검증이 주된 근거다.
- 수동 실측(봇 실행, 폼 → 입력 → 추가 분석 → 날짜 오류, 긴 결과의 메시지 분할에서 표 중간 잘림 여부):
  사용자 확인 대기.

## 8. 사용량

사주 명령도 기존 `rate-limiter`(사용자당 분당 한도, 일일 한도, 동시 실행 한도)를 그대로 거친다. 한도를
따로 두지 않는다.

## 9. 설정

| 키 | 기본값 | 설명 |
|---|---|---|
| `SAJU_SKILL_DIR` | 없음 | 스킬 디렉토리 절대경로. 비어 있으면 `!사주`는 설정 문제라고 답하고 `claude`를 띄우지 않는다 |
| `SAJU_SESSION_FILE` | `./data/saju-sessions.json` | 사주 스레드 → 세션 대응. 문서 질의응답의 `SESSION_FILE`과 다른 파일이어야 한다 |
| `SAJU_SANDBOX_DIR` | `os.tmpdir()/teamyg-bot-saju-sandbox` | 사주용 `claude`의 `cwd`. 시작 시 없으면 만든다. `REPO_ROOT` 안이면 시작 오류 |
| `SAJU_ENGINE_TIMEOUT_MS` | `30000` | MCP 서버가 `saju.py` 한 번을 기다리는 시간 |
| `PYTHON_BIN` | `python3` | 기존 키를 재사용한다 |
| `SAJU_TIMEOUT_MS` | `TIMEOUT_MS`와 같음 | 사주 `claude` 호출 타임아웃 |

음력 입력은 봇 호스트에 `korean-lunar-calendar` 파이썬 패키지가 있어야 한다. 없으면 스킬이 오류를
돌려주고 봇은 그대로 전한다.

## 10. 테스트

- `command.js`: `!사주`, `!사주 <입력>`, `!사주`가 중간에 있는 질문, 기존 figma·question 판정 불변.
- 격리 인자 빌더: `cwd`가 샌드박스, `--setting-sources ""`, `--tools ""`, `--strict-mcp-config`,
  `--allowed-tools`가 saju 도구 하나, 페르소나·밈 지시가 **없음**, 저장소 루트·`REPO_ROOT`가 인자 어디에도
  없음.
- `saju-mcp-server`: 인자 검증(셸 메타문자, 범위 밖 값 거부), `execFile` 인자 배열, 궁합 임시 파일 정리.
  `saju.py`는 가짜 실행 파일로 대체한다.
- 스레드 판정: 6.2절 표의 각 행.
- 수동 실측 1회: 실제 스킬로 폼 → 입력 → 결과 → 추가 분석까지 한 스레드에서 돈다.

## 11. README 갱신

- 「사주」 절: 명령, 스레드 규칙, `SAJU_SKILL_DIR`, 스킬은 저장소 밖에 둔다는 것과 그 이유.
- 「주의」 절: 사주 세션은 Bash를 열지 않고 `saju_calc` 하나만 쓴다는 것. 팀원의 생년월일시가 봇 호스트의
  세션 기록에 남는다는 것.
